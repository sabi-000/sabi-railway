# Complete Railway Deployment Guide for sabi-railway

## What is ready

This repository is prepared for automated deployment:

- `Dockerfile`: builds the image and runs Node.js
- `railway.json`: selects the Dockerfile, start command, and health check
- `package.json`: dependencies and `npm start`
- `index.js`: uses Railway's assigned `PORT`
- `BK_DATA_DIR=/data/bk-data`: persistent state and binary directory

## Deploy

1. Sign in to [Railway](https://railway.com).
2. Create a new Project.
3. Choose **Deploy from GitHub repo**.
4. Select `sabi-karami/sabi-railway`.
5. Wait for the Docker build and deployment to finish.

Railway reads `railway.json` automatically and starts the service with `npm start`.

## Required Volume

To preserve state, UUIDs, logs, and downloaded binaries:

1. Open the service.
2. Add a Volume from Settings or the Command Palette.
3. Set the mount path exactly to `/data`.
4. Redeploy the service.

`BK_DATA_DIR=/data/bk-data` is already configured in the Dockerfile.

## Domain and testing

Open Service → Settings → Networking and select **Generate Domain**. Test:

- `https://YOUR-DOMAIN/`
- `https://YOUR-DOMAIN/knight`
- `https://YOUR-DOMAIN/health`

The health endpoint should return JSON containing `ok: true`.

## TCP Proxy

The web panel uses HTTP/HTTPS. Raw TCP traffic requires Railway TCP Proxy. Enable TCP Proxy and select the service's internal port. Railway will provide a public hostname and port; clients must use that assigned port.

Because Railway networking has platform-specific constraints, not every TCP or TLS/SNI protocol is guaranteed to behave like it would on a VPS. Validate the web panel and `/health` endpoint first.

## Recommended variables

Set these under Railway → Variables:

```text
NODE_ENV=production
BK_DATA_DIR=/data/bk-data
PANEL_TOKEN=use-a-long-random-token
```

Never commit tokens to GitHub. Protocols can be enabled or disabled with the project's `ENABLE_*` environment variables.

## Troubleshooting

- Health check fails: inspect Logs and confirm the service uses Railway's `PORT` and binds to `0.0.0.0`.
- Settings disappear after restart: the Volume is not mounted at `/data`.
- Panel works but TCP does not: verify TCP Proxy and the public port generated by Railway.
- Build fails: inspect Docker/npm logs and redeploy after fixing the reported error.

## Security

Do not commit passwords, tokens, private UUIDs, or keys. Store all secrets only in Railway Variables. If the repository is public, review its contents before adding any secret.
